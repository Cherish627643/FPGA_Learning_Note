# 基于Arora-V的FPGA设计流程：三八译码器Verilog实现

## 一、三八译码器原理

### 1.1 基本概念

三八译码器有 **3 个输入端口** 和 **8 个输出端口**，8 个输出端口中的每一个端口对应三个输入端口的一种组合情况。

### 1.2 真值表逻辑

- 输入 `A2、A1、A0` 组成的十进制数是几，则对应编号的输出端口有效
- **低电平有效的芯片**：某位输出低电平，其余输出高电平
- **本设计采用高电平有效**：某位输出高电平，其余输出低电平（实际使用中更常见）

例如：

| A2 | A1 | A0 | 十进制值 | 有效输出 |
|----|----|----|----------|----------|
| 1  | 0  | 0  | 4        | Y4 为高（芯片版 Y4' 为低） |
| 0  | 0  | 0  | 0        | Y0 为高 |
| 0  | 1  | 1  | 3        | Y3 为高 |

### 1.3 核心功能

通过三个端口控制 8 个信号，但有局限性：**8 位里面每次仅有一位为有效电平，无法实现有两位及两位以上的端口同时有效**。

## 三、核心语法讲解

### 3.1 过程赋值语句（always 块）

```verilog
always @(*) begin
    // 过程赋值语句
end
```

- `always`：英文意为"总是"
- `@`：英文意为"关注"
- `(*)`：代表关注一切信号

**含义**：总是关注括号中列出的所有信号，当这些信号发生变化时执行块内语句。

`always @(*)` 中的 `*` 表示后续块中所有需要判断的信号（如本例的 `A0、A1、A2`）都会被自动列入敏感列表。

### 3.2 位拼接语法 `{...}`

```verilog
{A2, A1, A0}
```

将多个信号按从左到右的顺序拼接成一个新的多位信号。

- `A2、A1、A0` 都是单 bit 信号（一位宽），值只能是 0 或 1
- 拼接后得到 **3 位宽** 的新信号

**示例**：
- 若 `A2=1, A1=0, A0=0`，拼接得到 `3'b100`
- 若 `A2=0, A1=1, A0=1`，拼接得到 `3'b011`

### 3.3 位宽与进制表示

Verilog 中数据可指定位宽和进制：

| 进制 | 格式示例 | 等价含义 |
|------|----------|----------|
| 二进制 | `4'b1001` | 4 位二进制 1001 |
| 十进制 | `4'd9` | 4 位十进制 9 |
| 十六进制 | `4'h9` | 4 位十六进制 9 |
| 八进制 | `4'o11` | 4 位八进制 11 |

**位宽说明**：数字前的数字表示该数据占多少位宽。例如 `8'h5F` 表示该数据位宽为 8。

**重要特性**：用什么进制表示一个数，**不会改变值本身**，例如：
- `3'b100` ≡ `3'd4` ≡ `3'h4`

### 3.4 case 语句

```verilog
case (表达式)
    值1: 操作1;
    值2: 操作2;
    ...
    default: 默认操作;
endcase
```

- 根据括号内内容的值匹配对应分支
- 每个分支用冒号 `:` 分隔
- **必须以 `endcase` 结束**
- 若未列举所有可能情况，**必须使用 `default` 指定默认行为**，避免程序因异常情况赋予不可预测的值

## 四、三八译码器完整代码

```verilog
module decoder_3_8(
    A0, A1, A2,
    Y0, Y1, Y2, Y3, Y4, Y5, Y6, Y7
);
    input  A0, A1, A2;
    output Y0, Y1, Y2, Y3, Y4, Y5, Y6, Y7;
    
    reg Y0, Y1, Y2, Y3, Y4, Y5, Y6, Y7;
    
    always @(*) begin
        case ({A2, A1, A0})
            3'b000 : {Y0, Y1, Y2, Y3, Y4, Y5, Y6, Y7} = 8'b1000_0000;
            3'b001 : {Y0, Y1, Y2, Y3, Y4, Y5, Y6, Y7} = 8'b0100_0000;
            3'b010 : {Y0, Y1, Y2, Y3, Y4, Y5, Y6, Y7} = 8'b0010_0000;
            3'b011 : {Y0, Y1, Y2, Y3, Y4, Y5, Y6, Y7} = 8'b0001_0000;
            3'd4   : {Y0, Y1, Y2, Y3, Y4, Y5, Y6, Y7} = 8'b0000_1000;
            3'd5   : {Y0, Y1, Y2, Y3, Y4, Y5, Y6, Y7} = 8'b0000_0100;
            3'd6   : {Y0, Y1, Y2, Y3, Y4, Y5, Y6, Y7} = 8'b0000_0010;
            3'd7   : {Y0, Y1, Y2, Y3, Y4, Y5, Y6, Y7} = 8'b0000_0001;
            default: {Y0, Y1, Y2, Y3, Y4, Y5, Y6, Y7} = 8'b0000_0000;
        endcase
    end
    
endmodule
```

### 4.1 代码要点说明

1. **使用位拼接简化赋值**：原本每个分支需要写 8 个赋值（`Y0=1; Y1=0; ...`），通过 `{Y0, Y1, ..., Y7}` 位拼接合并为一句。
2. **进制选择技巧**：
   - 前 4 个 case 用 **二进制**：`3'b000`、`3'b001` 等，更直观对应 `A2A1A0`
   - 后 4 个 case 用 **十进制**：`3'd4`、`3'd5` 等，因为分析时是按十进制理解
3. **default 分支**：虽然已经列完所有情况，但保留 `default` 养成良好编程习惯。

## 五、reg 类型关键知识点

### 5.1 错误现象

初次编译时，Gowin 软件会提示 RTL 错误：

> 在 always 块里面相应一个非寄存器类型（non-reg）的信号上面赋值，这在语法上是不允许的。

### 5.2 修正方法

在 `always` 过程赋值语句中被赋值的信号，**必须定义为 `reg` 类型**：

```verilog
output reg Y0, Y1, Y2, Y3, Y4, Y5, Y6, Y7;
```

### 5.3 重要规则

> **凡是在 `always`（initial）这种过程赋值语句中被赋值的信号，都需要定义为 `reg` 类型**。

即使该信号本质上是输出端口，只要在 `always` 块中被赋值，就必须加 `reg`。
