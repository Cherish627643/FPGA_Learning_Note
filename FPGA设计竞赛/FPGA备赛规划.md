# 倒立摆项目全流程开发规划

结合你们有单片机、MATLAB基础但零FPGA经验的情况，**采用「算法仿真→单片机原型验证→FPGA模块化移植→系统联调」的梯度进阶路线**，最大化复用已有知识，避免同时踩硬件、算法、FPGA三个坑，6周节奏可控。

## 一、整体开发思路

你们的核心优势是懂单片机、会硬件调试，劣势是FPGA入门浅。因此不要一上来就写FPGA代码，而是分三步落地：

1. **先用MATLAB/Simulink做算法仿真**：先在软件里把倒立摆的PID参数、控制逻辑调通，得到理论参数范围，避免上板后盲目调参浪费时间；
2. **再用STM32单片机快速原型验证**：把整套硬件（传感器、电机、机械结构）全部跑通，踩掉所有硬件坑、机械坑，确认控制逻辑可行；
3. **最后移植到FPGA**：把单片机上验证过的逻辑，逐模块翻译成Verilog，每个模块先仿真验证再上板，最终实现全硬件控制。

这个路线的好处是：每个阶段只解决一个新问题，难度平滑过渡，和你们已有的知识高度衔接。

---

## 二、分阶段详细规划（对应6周备赛）

### 阶段1：算法建模与仿真（第1周，工具：MATLAB + Simulink）

**核心目标**：在软件里验证倒立摆控制方案可行性，得到PID参数的大致范围，给后续上板做基准。

#### 具体操作步骤

1. **搭建倒立摆动力学模型**
    - 新手不推荐从零推导公式，直接用Simulink自带的示例模板：
        - 在Simulink库中搜索 `Inverted Pendulum`，调用自带的一级倒立摆模型；
        - 输入你们实际硬件的参数：摆杆长度、质量、电机力矩系数、摩擦系数等，没有精确值就用典型值。
    - 也可以用Simscape多体物理库搭建简易模型，可视化程度更高。
2. **搭建PID控制器**
    - 用Simulink的PID Controller模块，搭建「角度环+速度环」双环控制（倒立摆经典结构）：
        - 外环：角度环，输入摆杆角度偏差，输出期望角速度；
        - 内环：角速度环，输入角速度偏差，输出电机PWM控制量。
    - 加入饱和限幅模块，限制PWM最大输出，对应真实电机的最大电压。
3. **仿真调参（核心产出）**
    - 用**临界比例度法**快速调参：
        1. 先把Ki、Kd置0，逐步增大Kp，直到摆杆出现等幅振荡，记录临界Kp和振荡周期；
        2. 按公式计算出初始Kp、Ki、Kd；
        3. 微调参数，直到满足：起摆时间<2s、稳态角度误差<±1°、受外力扰动后1s内恢复。
    - 仿真测试三个场景：自动起摆、稳态直立、外力冲击恢复。
4. **阶段产出**
    - 一组PID初始参数（Kp、Ki、Kd）；
    - 仿真波形图：角度响应曲线、PWM输出曲线；
    - 明确系统的响应速度、超调量、稳态误差指标。

#### 为什么先做这一步

很多新手上来直接上板调PID，调一周都调不稳，最后发现是机械结构问题还是参数问题根本分不清。仿真先给你一个「理论可行解」，上板只需要微调，至少能排除算法方向错误。

### 阶段2：单片机快速原型验证（第2周，工具：STM32CubeIDE + STM32开发板）

**核心目标**：用你们最熟悉的单片机，把整套硬件全链路跑通，验证机械结构、传感器、电机驱动都没问题，同时把PID参数在真实硬件上校准好。

#### 具体操作步骤

1. **外设驱动开发（开环验证）**
    - MPU6050六轴传感器：I2C接口读取原始数据，通过姿态解算得到摆杆角度和角速度，串口打印验证数据平稳、无漂移；
    - L298N电机驱动：定时器输出PWM，控制电机正反转、调速，验证电机响应正常；
    - 光电编码器：读取电机转速/位置，用于速度环反馈。
2. **闭环控制实现**
    - 把Simulink里的PID算法翻译成C语言，烧录进STM32；
    - 先测试起摆：电机先往复摆动，利用能量积累把摆杆甩起来；
    - 再测试稳态平衡：摆杆接近垂直位置时切入PID控制，观察稳定效果；
    - 对照仿真参数微调，直到能稳定直立10秒以上，抗轻微触碰。
3. **阶段产出**
    - 一套能稳定工作的单片机倒立摆系统；
    - 校准后的传感器零偏、实际可用的PID参数；
    - 确认机械结构、电机、传感器全部正常工作，没有硬件故障。

#### 关键意义

这一步是「踩坑期」，机械摩擦、传感器漂移、电机死区、电源波动这些问题，在单片机上排查效率是FPGA的3倍以上。把这些坑全踩完，后面FPGA阶段只需要专注逻辑移植，不用怀疑硬件。

---

### 阶段3：FPGA模块化移植与仿真（第3-4周，工具：高云云源EDA + 内置仿真器）

**核心目标**：把单片机上验证过的逻辑，逐模块翻译成Verilog，每个模块先通过仿真验证正确性，再上板。

#### 模块拆分与移植顺序（和单片机一一对应）

|单片机功能|FPGA对应实现|学习难度|验证方式|
|---|---|---|---|
|系统时钟、定时器|时钟分频、计数器|★☆☆|仿真看时钟频率|
|GPIO按键、LED|输入输出端口、按键消抖|★☆☆|上板直测|
|定时器PWM输出|PWM发生器（计数器+比较器）|★★☆|仿真看占空比 + 示波器测|
|I2C外设读MPU6050|I2C主机状态机|★★★|仿真看I2C时序 + 上板读数据|
|PID控制算法|数字PID硬件逻辑|★★★|仿真输入误差，看输出PWM|
|编码器测速|编码器脉冲计数、测速逻辑|★★☆|仿真输入脉冲，看速度计算值|

#### 仿真（Simulate）怎么用

这是FPGA开发最核心的调试手段，相当于单片机的「串口打印调试」，**每个模块必须先仿真通过再上板**。

1. **什么是Testbench** 给设计的模块输入模拟信号（时钟、复位、数据），观察输出波形是否符合预期，不用接真实硬件。
2. **工具选择** 直接用高云云源EDA自带的仿真功能，不用额外装ModelSim，新手足够用。
3. **以PID模块为例的仿真步骤**
    - 编写Testbench文件：生成50MHz时钟、复位信号，输入固定的角度误差值；
    - 运行仿真，观察输出的PWM占空比是否和单片机计算的一致；
    - 再输入动态变化的误差值，观察PID输出的响应速度、积分累积是否正确。
4. **高效技巧** 把单片机里的测试数据（比如不同角度对应的PWM值）做成「黄金参考」，FPGA仿真输出和它对比，完全一致就说明逻辑没错。

#### 阶段产出

- 每个模块独立的Verilog代码；
- 每个模块的仿真波形图和验证报告；
- 顶层模块拼接完成，管脚分配完成。

### 阶段4：FPGA上板联调与优化（第5周，工具：高云云源EDA + 示波器 + 逻辑分析仪）

**核心目标**：全系统上板联调，实现稳定倒立，加入拓展功能。

#### 联调步骤（和单片机完全一致）

1. **开环逐个验证**
    - 先测LED、按键：确认IO口正常；
    - 再测PWM输出：示波器测电机引脚，确认占空比可调、频率正确；
    - 再测传感器：通过逻辑分析仪抓I2C波形，确认MPU6050数据读取正确。
2. **闭环联调**
    - 先切入比例控制（Kp），看摆杆是否有修正动作，确认方向没反；
    - 逐步加入Ki、Kd，参照单片机的参数微调，直到稳定直立；
    - 测试起摆、稳态、抗干扰三个场景。
3. **拓展功能加分**
    - 按键控制：起摆/复位、切换模式；
    - LED状态指示：平衡状态、故障状态；
    - 位置控制：控制云台左右移动，同时保持摆杆直立。

## 三、关键知识衔接：单片机 → FPGA

帮你把已有知识对应过去，降低学习门槛：

1. **时钟**：单片机的8MHz晶振+定时器 → FPGA的系统时钟+计数器分频，本质都是计数；
2. **PWM**：单片机定时器CCR → FPGA的计数器+比较器，原理完全一样；
3. **I2C**：单片机调用库函数 → FPGA手写状态机（起始、发送、应答、停止），时序逻辑和单片机底层操作一致；
4. **PID算法**：单片机C语言循环计算 → FPGA每个时钟周期计算一次，公式完全相同，只是用寄存器代替变量；
5. **调试**：单片机串口打印 → FPGA仿真看波形 + 板载LED指示关键状态。

---

## 四、避坑提醒

1. **不要跳过单片机阶段**：直接上FPGA出问题时，你分不清是逻辑错了、时序错了还是硬件坏了，排查效率极低；
2. **不要省略仿真**：每个模块先仿真再过，上板调试时间至少省一半；
3. **PID参数不用硬套仿真值**：真实机械有摩擦、死区，上板都要微调，仿真只给范围；
4. **先开环、后闭环**：永远先确认每个外设单独工作正常，再接闭环，这是调试铁律。
