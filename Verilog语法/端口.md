在 Verilog 里，**端口列表就是模块的“引脚列表”**，写在模块名后面的括号里，用来[定义这个模块](模块的定义.md)和外部怎么连接。

```verilog
module mux2(
    input  a,
    input  b,
    input  sel,
    output y
);
    assign y = sel ? b : a;
endmodule
```

这里的 `(input a, input b, input sel, output y)` 就是端口列表。

---

## 1. 端口列表是什么意思？

端口列表描述了一个模块的**输入、输出、双向接口**，相当于==**芯片的引脚。**==

| 端口方向 | 含义 |
|---|---|
| `input` | 输入，外部信号进来 |
| `output` | 输出，模块信号出去 |
| `inout` | 双向，既能输入也能输出 |

例如 `mux2` 模块：

- `a`、`b` 是输入数据；
- `sel` 是选择信号；
- `y` 是输出结果。

当你在另一个模块里例化它时，就要把这些端口连起来：

```verilog
mux2 u_mux2(
    .a   (a),
    .b   (b),
    .sel (sel),
    .y   (y)
);
```

所以端口列表的作用是：**告诉上层模块，我这个模块有哪些引脚，分别怎么连接。**

---

## 2. 为什么[仿真的时候不用写端口列表？](仿真时候不写端口列表的本质.md)

因为仿真时写的顶层模块通常是 **testbench**，它不需要和外部硬件连接。

```verilog
module tb;   // 注意：这里没有端口列表
    reg  a, b, sel;
    wire y;

    mux2 u_mux2(
        .a(a),
        .b(b),
        .sel(sel),
        .y(y)
    );

    initial begin
        a = 0; b = 1; sel = 0;
        #10 sel = 1;
        #10 $finish;
    end
endmodule
```

`tb` 是仿真顶层，它不会被其他模块例化，也没有上级模块来连接它。  
仿真器直接把它当作**根模块**运行，所以它不需要端口。

它内部自己声明 `reg`、`wire` 信号，自己产生时钟和激励：

```verilog
reg clk = 0;
always #5 clk = ~clk;
```

这些信号不是端口，而是 testbench 内部变量。  
它们直接连接到被测试模块（DUT）的端口上。

---

## 3. 关键区别

| 场景 | 是否需要端口列表 | 原因 |
|---|---|---|
| 要被例化的子模块 | 必须写 | 上层需要通过端口连接它 |
| 综合到 FPGA 的顶层模块 | 必须写 | 需要映射到实际芯片引脚 |
| 仿真用的 testbench 顶层 | 通常不写 | 它是仿真根模块，没有上级连接，不综合成硬件 |
| 纯内部模块 | 可以没有端口 | 如果它只通过内部信号工作，不需要外部接口 |

所以不是“仿真时不用写端口列表”，而是：

> **仿真顶层 testbench 不需要端口列表，因为它不需要被连接，也不综合成实际电路。**

如果你在仿真里写了一个子模块，比如 `mux2`，它仍然必须写端口列表，因为 testbench 要例化它、连接它。

## 4. 对比理解

### 综合用的顶层模块

```verilog
module top(
    input  wire clk,
    input  wire rst_n,
    input  wire [7:0] din,
    output wire [7:0] dout
);
    // 要映射到 FPGA 引脚，所以必须有端口
endmodule
```

### 仿真用的 testbench

```verilog
module tb;   // 没有端口
    reg clk;
    reg rst_n;
    reg [7:0] din;
    wire [7:0] dout;

    top u_top(
        .clk(clk),
        .rst_n(rst_n),
        .din(din),
        .dout(dout)
    );

    initial begin
        clk = 0;
        forever #5 clk = ~clk;
    end
endmodule
```

`tb` 没有端口，但它内部有 `clk`、`rst_n`、`din` 这些信号，用来驱动 `top` 的端口。

---

## 5. 一句话总结

**端口列表是模块对外的引脚定义，用来连接和综合。**  
**仿真顶层 testbench 不需要与外部连接，也不综合成硬件，所以可以不写端口列表；但被它例化的 DUT 模块仍然必须写端口列表。**
