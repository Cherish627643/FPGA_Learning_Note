
# 操作步骤
### 🚀 第一步：打开模型并跑通第一个仿真

1.  **打开Simulink模型**：在MATLAB命令窗口输入以下命令，打开用于纯仿真验证的模型。
    ```matlab
    open_system("s_qube2_bal_rl.slx")
    ```
2.  **运行仿真**：模型打开后，直接点击Simulink工具栏的 **“Run”** 按钮。模型会自动加载一个预训练的强化学习（RL）智能体（通常是`QubeIPBalDDPG09.mat`文件），并开始仿真。
3.  **观察结果**：仿真运行后，双击模型中的 **“Rotary Arm (deg)”** 和 **“Inverted Pendulum (deg)”** 示波器模块，观察旋转臂和摆杆的角度变化曲线。你应该能看到摆杆在RL控制器的驱动下，从初始位置被“甩”起并稳定在竖直向上的平衡位置。

### 🧠 第二步：理解模型的结构

这个模型清晰地展示了Quanser官方示例中“分层控制”的架构，理解它对你后续的设计很有帮助。

*   **外环 (Outer Loop)**：这是模型的核心，负责生成“参考轨迹”。它由两个RL智能体组成：
    *   **Swing-up Agent**：当摆杆在下方时，这个智能体负责计算如何把摆杆“甩”到接近竖直的位置。
    *   **Mode-select Agent**：当摆杆接近竖直时，这个智能体负责切换控制模式，将目标角度设置为精确的竖直位置（π弧度）。
*   **内环 (Inner Loop)**：这是一个低层级的**PD控制器**，它接收外环给出的“参考角度”，并计算出实际的**电机电压**，以快速稳定地跟踪这个角度。

### 🔧 第三步：将RL控制器替换为你的PID控制器

你的目标是进行PID控制，所以需要把外环的RL智能体替换掉，直接用你的PID控制器来生成电机电压指令。

1.  **定位RL Agent模块**：在模型中找到名为 **“Outer Loop Control”** 的子系统，双击进入，你会看到 `RL_Swing Up` 等RL Agent模块。
2.  **替换为PID Controller**：删除这些RL Agent模块。从Simulink库中拖入 **PID Controller** 模块。
3.  **连接信号**：
    *   **PID输入**：连接模型的反馈信号，即摆杆角度 `φ` 的偏差（目标角度 `0` 减去实际角度 `φ`）。
    *   **PID输出**：将PID的输出连接到原本RL Agent输出的地方，即**内环PD控制器的参考输入端**，或者，如果你想自己设计整个控制器，可以直接将PID输出连接到**电机电压输入端口**（注意限幅到±12V）。
4.  **设置PID参数**：双击PID模块，将你在MATLAB仿真中整定好的 `Kp`、`Ki`、`Kd` 参数填进去。**建议先只用P控制**，确认系统有正确的响应方向后，再逐步加入I和D。

### ⚙️ 第四步：仿真配置与调试

*   **求解器设置**：这个模型包含Simscape物理建模，需要使用隐式求解器。在Simulink菜单 **Simulation > Model Configuration Parameters** 中，将 **Solver** 设置为 **`ode23t`** 或 **`ode15s`**。
*   **调试建议**：
    *   **符号检查**：确保你的PID反馈符号正确。给一个小的正向角度偏差，观察电机是否朝正确的方向转动来“扶正”摆杆。如果方向反了，系统会立刻发散。
    *   **限幅保护**：在PID输出后务必加一个 **Saturation** 模块，限制在 `[-12, 12]` 之间，防止输出过大的电压指令。

### 💡 下一步建议

在你能用自己的PID控制器在Simulink中稳定住摆杆后，就可以考虑进行**硬件在环（HIL）测试**了。资源包中通常还包含一个用于真实硬件闭环控制的模型，例如 **`q_qube2_bal_rl_hw.slx`**。你可以参照类似的步骤，将你的PID控制器部署到这个模型上，在真实的QUBE硬件上测试你的算法。

如果在替换控制器或调试过程中遇到具体的报错，可以随时把错误信息发给我，我再帮你一起看看。

## 逻辑

根据这张 Simulink 模型截图，这是一个**基于强化学习（RL）的 Quanser Qube-Servo 3 倒立摆控制仿真模型**。

整个模型的逻辑可以清晰地划分为“强化学习决策环”和“物理对象仿真环”两大部分。简要分析如下：

### 🔄 核心信号流向（从左到右，从右到左反馈）

1. **状态观测与反馈（右侧 `observations` 模块）**
   物理模型 `Qube-Servo 3 Pendulum Model` 解算出四个状态量：`theta`（旋转臂角度）、`alpha`（摆杆角度）、`theta_dot`（旋转臂角速度）、`alpha_dot`（摆杆角速度）。这些状态量被送入 `observations` 模块，打包成观测向量，反馈给左侧的 `RL Agent`。

2. **奖励计算（左侧 `qr reward` 模块）**
   该模块接收观测状态和上一时刻的动作 `u(k-1)`，计算出当前动作的奖励 `reward`，并输出 `stop` 和 `isdone` 信号。在强化学习中，奖励函数的设计通常是：摆杆越接近竖直向上、旋转臂越接近中心，奖励越高；如果摆杆倒下或超出物理限制，则触发 `isdone` 终止本轮仿真。

3. **强化学习决策（核心 `RL Agent` 模块）**
   `RL Agent` 接收到观测值和奖励后，基于其内部训练好的神经网络（图中可见网络结构图标），计算出当前状态下最优的电机控制动作 `action`（记为 `u`）。

4. **动作限幅与执行（`+/-10V` 模块）**
   `RL Agent` 输出的动作 `u` 经过 `+/-10V` 饱和模块限幅，确保送给物理模型的电压指令在 Quanser Qube-Servo 3 的物理限制范围内（±10V），防止损坏电机或模型发散。

5. **物理对象仿真（`Qube-Servo 3 Pendulum Model` 模块）**
   这是系统的被控对象。它接收限幅后的电压 `u(V)` 以及初始条件 `alpha0`（由 `IC0` 模块提供，图中为 `ic_alpha0`），运行 Simscape 多体动力学和电气模型，解算出下一时刻的四个状态量。

6. **数据可视化（右侧 `R2D` 模块与 Scope）**
   `theta` 和 `alpha` 经过 `R2D`（Radians to Degrees，弧度转角度）模块转换后，分别送入 `Rotary Arm (deg)` 和 `Inverted Pendulum (deg)` 两个示波器，用于观察旋转臂和摆杆的角度变化曲线。

---

### 💡 对你当前任务的指导意义（如何替换为 PID）

结合你之前的备赛规划，你现在的目标是**用你整定好的 PID 替换掉这个 RL 控制器**。根据这张图，你需要做以下修改：

*   **删除的部分**：删掉左侧的 `RL Agent` 和 `qr reward` 模块，以及右侧的 `observations` 模块（因为 PID 不需要奖励和观测打包）。
*   **接入 PID 的位置**：
    1.  从物理模型输出的 `alpha`（摆杆角度）引出一根线。
    2.  用常数模块 `0` 减去 `alpha`，得到摆杆角度误差 `e = 0 - alpha`。
    3.  将误差 `e` 输入到你自己的 **PID Controller** 模块。
    4.  将 PID 的输出连接到 `+/-10V` 饱和模块的输入端。
    5.  饱和模块的输出依然连接到 `Qube-Servo 3 Pendulum Model` 的 `u(V)` 输入端。
*   **初始条件**：保留 `IC0` 模块，用于设置摆杆的初始角度（例如设为 `10度` 或 `0.1745 rad`），以便在仿真开始时测试 PID 能否将摆杆“扶正”。
*   **调试建议**：在替换完成后，先只使用 P 控制（Ki=0, Kd=0），给一个小的初始角度偏差，观察摆杆是否有向竖直方向运动的趋势。如果方向反了，说明 PID 输入端的符号需要取反。

### ⚙️ 当前模型配置提示
截图底部右侧显示求解器为 `ode2`（看起来像 `ode23t` 或 `ode15s` 的缩写，这是 Simscape 物理模型推荐的隐式求解器），这是正确的。替换控制器后，建议保持求解器不变，并将 `Max step size` 设置为 `0.001` 或 `0.005` 以保证仿真精度。

建议你先点击“运行”跑通这个原始模型，观察 RL 智能体是如何控制摆杆的，建立直观感受后，再动手删掉 RL 模块，换成你的 PID 控制器进行调试。

## 如何创建PID controller

### 🔍 先澄清概念：PID控制器 ≠ 反馈控制器

**PID控制器**的中文标准叫法是**PID控制器**（或PID调节器），它只是“反馈控制器”这个大类里的一种。反馈控制器是一个更宽泛的概念，还包括LQR、状态反馈、滑模控制等。所以在Simulink里，你**搜“PID”能找到模块，搜“反馈控制器”是找不到的**。

---

### 📦 不需要“创建”，直接从库里拖

Simulink是图形化编程，**PID Controller是一个现成的模块**，不需要你写代码或新建文件。你只需要：

1. **打开你“另存为”的新模型**（比如 `sim_qube3_bal_pid.slx`）。
2. **打开库浏览器**：点击Simulink上方工具栏的 **“库浏览器”**（Library Browser）图标。![[Pasted image 20260925160501.png]]
3. **搜索模块**：在库浏览器的搜索框里输入 **`PID Controller`**。![[Pasted image 20260925160432.png]]
4. **拖入模型**：找到 `Simulink -> Continuous -> PID Controller`，用鼠标把它拖到你的模型画布上。
5. **双击设置参数**：拖进来后，双击这个模块，就能设置 `P`、`I`、`D` 的值了。

---

### 🔧 在你的模型中替换RL Agent的具体操作

结合你截图里的模型，按以下步骤做：

1. **删除RL相关模块**：选中 `RL Agent`、`qr reward`、`observations` 这三个模块，按 `Delete` 删掉。
2. **拖入PID Controller**：从库浏览器拖入一个 **PID Controller** 模块。
3. **接线**：
   - 从物理模型输出的 `alpha`（摆杆角度）引出一根线。
   - 加一个 **Constant** 模块，值为 `0`（目标角度）。
   - 用 **Sum** 模块做减法：`0 - alpha`，得到角度误差 `e`。
   - 把 `e` 接入 PID Controller 的输入端口。
   - PID Controller 的输出，连接到原来 `+/-10V` 饱和模块的输入端。
4. **设置初始条件**：保留 `IC0` 模块，把 `alpha0` 设为一个小角度（比如 `0.1` 弧度，约5.7°），用来测试PID能否把摆杆扶正。
5. **运行仿真**：点击“运行”，观察示波器里摆杆角度是否收敛到0。

---

### 💡 设置PID参数时的注意事项

双击PID Controller模块，你会看到：
- **P**：比例增益，先设一个较小的值（比如50）。
- **I**：积分增益，**先设为0**。摆杆平衡控制通常不需要积分，或者只需要很小的积分。
- **D**：微分增益，先设一个较小的值（比如2）。![[Pasted image 20260925161135.png]]
- **抗积分饱和**：在模块的“Advanced”选项卡里，勾选 **Limit output**，上下限设为 `[-10, 10]`（对应±10V），并选择 **Anti-windup** 方式为 `clamping`。这一步很重要，防止积分项累积过大导致系统发散。![[Pasted image 20260925161323.png]]

## PID controller 选型

选**第一个 `PID Controller`**（位于 `Simulink -> Continuous` 下的那个）。

### 🎯 为什么选这个？

你现在的场景是**纯Simulink软件仿真**，被控对象（Qube-Servo 3物理模型）是连续的物理系统，所以要用**连续时间的标准PID控制器**。这个模块最通用、参数设置最直观，完全满足你当前的阶段一需求。

### ❌ 为什么其他的不选？

*   **`PID Controller (2DOF)`**：二自由度PID，多了一套设定点权重参数。你的倒立摆目标角度恒定为0，属于纯调节问题，不需要这种复杂结构，会增加调参难度。
*   **`Discrete PID Controller`**：离散PID。只有当你需要模拟数字控制器（比如以后移植到单片机或FPGA，需要固定采样周期）时才用。现在做连续仿真，不需要。
*   **HDL Coder 下的 `Discrete PID Controller`**：这是用于**直接生成FPGA硬件代码**（Verilog/VHDL）的模块，配置极其复杂，完全不适合当前阶段。
*   **`Varying PID Controller`**：变增益PID，适用于参数随状态剧烈变化的非线性系统，属于过度设计，没必要。

拖进去接好线，设好初始角度（比如 `alpha0 = 0.1` 弧度），直接点运行，观察示波器里摆杆角度的变化。如果方向反了（角度越来越大），把PID输入的误差符号反过来（即改为 `alpha - 0`）即可。

## 接线

在 Simulink 里“接线”其实就是**用鼠标拖拽连线**。结合你目前的模型（`sim_qube3_bal_pid.slx`），我带你一步步操作，确保逻辑正确。

整个接线逻辑是：**目标角度(0) - 实际角度(alpha) = 角度误差 -> PID控制器 -> 电压限幅 -> 物理模型**。

### 🧩 第一步：拖入新模块
从库浏览器（Library Browser）中拖出以下模块放到模型空白处：
*   **1个 `Constant` 模块**（常量）：在 `Simulink -> Sources` 里找。
*   **1个 `Sum` 模块**（求和）：在 `Simulink -> Math Operations` 里找。
*   **1个 `PID Controller` 模块**（你刚选的那个）。

### 🔌 第二步：开始接线（核心步骤）

**1. 生成目标角度（0）**
*   双击 `Constant` 模块，把值设为 **`0`**。
*   将 `Constant` 模块的输出端（箭头），用鼠标拖线连接到 `Sum` 模块的**第一个输入端（正号，+）**。

**2. 引入实际反馈角度（alpha）**
*   找到你模型中间的 **`Qube-Servo 3 Pendulum Model`** 模块。
*   在这个模块的右侧，找到一个输出端口叫 **`alpha (rad)`**（摆杆角度）。
*   从这个 `alpha (rad)` 端口拖出一根线，连接到 `Sum` 模块的**第二个输入端（负号，-）**。
*   *（提示：如果 Sum 模块只有两个正号，双击 Sum 模块，把符号列表改成 `|+-`）*

**3. 接入PID控制器**
*   从 `Sum` 模块的输出端，拖线连接到 **`PID Controller`** 模块的输入端口。
*   这样，进入 PID 的就是 `(0 - alpha)` 的角度误差。

**4. 输出控制电压**
*   从 **`PID Controller`** 模块的输出端，拖线连接到原模型中那个 **`+/-10V`** 的饱和模块的输入端。（如果你之前把这个饱和模块删了，就直接连到 `Qube-Servo 3 Pendulum Model` 的 `u (V)` 输入端）。
*   如果你用PID自身的饱和，连线就可以直接连到物理模型的 `u (V)` 输入端口。

### ⚠️ 第三步：检查连线与参数

完成后，你的数据流应该是这样的：
`Constant(0)` ➡️ `Sum(+)`
`Qube(alpha)` ➡️ `Sum(-)`
`Sum` ➡️ `PID`
`PID` ➡️ `+/-10V` ➡️ `Qube(u)`

**最后，去双击设置你的 PID 参数：**
*   在“主要”选项卡：**P = 50, I = 0, D = 2**（先用这组参数跑通，再微调）。
*   在“饱和”选项卡：记得勾选“限制输出”，上限设 `10`，下限设 `-10`，抗积分饱和选 **“钳位”**。

### 🎯 第四步：运行并检验正负方向（极关键！）

接好线后，双击 `IC0` 模块，把初始角度 `alpha0` 设为 `0.1` 弧度（约5.7度）。
点击运行，观察 `Inverted Pendulum (deg)` 示波器。

*   **如果摆杆角度慢慢回到 0 附近**：恭喜，接线和符号完全正确！
*   **如果摆杆角度直接冲向 90 度（倒下）**：说明反馈方向反了。解决方法是：把 `Sum` 模块的两个输入换个位置（即 `alpha - 0`），或者双击 Sum 模块把符号改成 `|-+`。倒立摆的控制逻辑就是如此，符号错了会直接加速倒下。

## 报错
计算在模块图 'sim_qube3_bal_pid' 的 "配置参数" 对话框中指定的 'StopTime' 的表达式 'Tf' 时出错。 原因: 函数或变量 'Tf' 无法识别。 变量 'Tf' 不存在。 建议的操作 将数据从文件加载到基础工作区中。

这是因为模型原本的“停止时间”被设置成了一个变量 `Tf`，但 MATLAB 的基础工作区里目前没有定义这个变量，导致 Simulink 找不到它。你有两种快速的解决办法：

### 方法一：直接改成固定数值（最省事，推荐）

1. 在 Simulink 顶部菜单栏点击 **“建模”** -> **“模型配置参数”**（或点击上方工具栏的小齿轮图标）。
2. 在左侧选择 **“求解器”**。
3. 找到右侧的 **“停止时间”**（StopTime）输入框，把原本的 `Tf` 直接改成数字 **`10`**（代表仿真10秒）。
4. 点击 **“确定”**，再点运行即可。

### 方法二：在命令行定义变量（不改模型）

在 MATLAB 下方的**命令行窗口**（Command Window）中，直接输入：
```matlab
Tf = 10;
```
按回车。这样工作区里就有 `Tf` 这个变量了，接着直接点击 Simulink 的“运行”按钮就不会再报错。

---

### 💡 额外提醒：可能会遇到下一个报错

你刚才删掉了 RL 模块，现在换成纯 PID 控制。如果模型内部还引用了其他为 RL 准备的变量（比如 `Ts` 采样时间、`max_steps` 等），接下来可能还会报类似的“找不到变量”错误。

**如果继续报错，建议你直接运行官方提供的初始化脚本**。在 MATLAB 命令行输入：
```matlab
open('setup_qube3_inv_pen_rl.mlx')
```
打开这个 Live Script 后，找到里面**定义物理参数和仿真参数**的代码段（通常在脚本的最前面），选中并运行它们（点击代码段左侧的“运行”小三角）。等工作区加载完所有变量后，再运行你的 `sim_qube3_bal_pid` 模型，就不会再报缺变量的错了。

别担心，这里有个小误会：**加载物理参数（`Jp`、`Tf` 等）和强化学习的智能体（agent）完全没有关系，两者是独立的。**

你之所以觉得“没有 agent 无法运行官方文件”，是因为如果你点击了 Live Script 顶部的全局“运行”，它会从头到尾把所有代码跑一遍，包括加载/训练 RL Agent，自然就会因为缺智能体而报错或卡住。

你**不需要**跑完整的脚本，只需要“抠”出最前面的参数初始化代码。

1. 在 MATLAB 命令行输入 `open('setup_qube3_inv_pen_rl.mlx')` 打开脚本。

### 💡 终极省心技巧：建一个初始化脚本

为了避免每次打开 MATLAB 都要重新加载变量（一旦重启 MATLAB，工作区就空了），建议你：
1. 在 MATLAB 左上角点击“新建脚本”。
2. 把上面那些变量定义（或者你从官方脚本里抠出来的参数）全都复制进去。
3. 保存为 `init_qube_params.m`，放在和模型同一个文件夹里。
4. 以后每次打开 MATLAB，只要在命令行输入 `init_qube_params`，参数就全加载好了，再点运行模型就不会报错了。

## 报错2

这两个都是常见的提示，一个无关紧要，一个需要你动手配置一下。分开来说：

### 🟢 警告1：输出端口3未连接
**这完全没关系，可以直接忽略。**
你现在的 PID 控制只用到了 `alpha`（摆杆角度，输出端口2）。`theta_dot`（旋转臂角速度，输出端口3）和 `alpha_dot`（端口4）暂时不需要，所以悬空会弹个警告。
*   **解决办法（可选）**：如果嫌提示烦，可以在 Simulink 库浏览器搜一个叫 `Terminator` 的模块，拖出来接到端口3和端口4上，警告就会消失。

---

### 🟡 警告2：无法确定默认工具链（这个需要处理）
**原因**：你的模型里包含了 Simscape 物理模型和 MATLAB Function，Simulink 在运行前需要把它们编译成 C 语言代码，但 MATLAB 没找到可用的 C 编译器。如果不解决，点运行大概率会直接报错终止。

**解决办法（按顺序尝试）**：

**第一步：在 MATLAB 里绑定编译器**
1. 回到 MATLAB 主界面，在**命令行窗口**输入：
   ```matlab
   mex -setup
   ```
2. 按回车。MATLAB 会自动扫描你电脑里的编译器。
3. 如果屏幕上列出了 `Microsoft Visual C++ 2022` 或其他版本，输入对应的数字（通常是 `1` 或 `2`）并回车确认即可。

**第二步：如果 `mex -setup` 提示找不到编译器**
说明你电脑里没装合适的 Visual Studio。
1. 去微软官网下载 **Visual Studio Community**（社区版，免费）。
2. 安装时，**必须勾选“使用 C++ 的桌面开发”**（Desktop development with C++）这个工作负载。
3. 安装完成后，重启 MATLAB，再次运行 `mex -setup` 进行绑定。

**第三步：如果装的是最新版 Visual Studio（比如 VS 2026）**
MATLAB 往往不支持太超前的编译器。如果 `mex -setup` 仍然找不到，建议去下载 **Visual Studio 2019 或 2022 社区版**，只勾选 C++ 桌面开发即可。安装好后再运行 `mex -setup`。

---

1. 先去命令行跑 `mex -setup`。
2. 绑定好编译器后，切回模型点击“运行”。
