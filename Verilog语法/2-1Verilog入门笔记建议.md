## 四、还可以改进的地方

如果想让这份笔记更好，可以考虑下面几点，但都不是必须的。

### 1. 第 13 章 function / task 可以再精简（这个地方不用管）

`function` 和 `task` 在入门阶段确实不常用，现在写得比较全，但可以再压缩一点，或者明确标注“初学可跳过，用到再回来看”。（agent修改时只需标注即可）

### 2. 第 14 章组合电路可以加一个“优先编码器”

常用组合电路里，MUX、加法器、译码器、ALU 都有了，可以再加一个**优先编码器**，和 `if-else if` 的优先级对应，帮助理解优先级逻辑。

### 3. 第 15 章可以加一个“按键消抖”

分频、边沿检测都有了，按键消抖是这两者的综合应用，也是 FPGA 入门最常做的小项目之一。可以简单给一个计数器消抖的模板。

### 4. 第 16 章状态机可以加一个“序列检测”例子

状态机现在有通用模板，但缺一个具体例子。序列检测（比如检测 `1011`）是状态机最经典的应用，可以补一个 Moore 或 Mealy 的实现。

### 5. 第 17 章可以加“自检查 testbench”

现在的 testbench 是“加激励、看波形”，可以再补一点“自动比较输出”的写法，比如：

```verilog
if (dout !== 8'hA5) begin
    $display("ERROR at time %t: dout=%h", $time, dout);
    $stop;
end
```

这样仿真不用一直盯着波形，更适合稍大一点的设计。

### 6. 第 18 章可以加“综合报告怎么看”

现在讲了流程和约束，但没讲综合后怎么看资源占用、时序报告。入门可以简单提一句：

- 资源：LUT、FF、BRAM、DSP 用了多少
- 时序：最高频率、建立/保持时间是否满足
- 警告：锁存器、多驱动、未约束路径

### 7. 第 20 章可以加一个“上板前检查清单”

现在有“读代码 checklist”，可以再加一个“上板前 checklist”：


- [ ] 顶层模块名和工程设置一致？
- [ ] 所有端口都做了引脚约束？
- [ ] 时钟引脚选的是全局时钟脚？
- [ ] 复位电平对不对？按键是低有效还是高有效？
- [ ] 综合有没有 latch、多驱动、未约束警告？
- [ ] 时序报告有没有违例？
- [ ] 比特流下载后，LED/串口有没有预期反应？


### 8. 可以加一个“最小可运行工程”附录

给一个从零到下载的最小例子，比如：

- 一个按键控制 LED 亮灭
- 或者一个分频器让 LED 闪烁

这样初学者可以照着走一遍完整流程。
